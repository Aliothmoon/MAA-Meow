# 方案：任务日志页保留停止任务与快捷选项

状态：已按方案实现代码并补充回归测试，22 项单元测试与 Debug 构建通过，尚未真机验证。日志页始终保留停止任务和快捷选项；空闲时停止任务置灰且不可点击。

分析基线：`main`，提交 `8b1caae6`。

## 1. 问题与依据

用户在「任务 → 一键长草」启动任务后，会自动进入日志页。日志页没有底部操作栏，因此查看运行情况之后，还需要切回其他标签页才能停止任务或开启熄屏挂机。

源码和历史记录显示：

- `PanelTab.canShowTaskActions()` 只允许 TASKS、AUTO_BATTLE、TOOLS 显示操作栏，至少在提交 `09d572cf` 中已存在。
- `BackgroundTaskView` 用这个条件同时控制主操作和快捷选项；快捷选项收起条件、设置搜索跳转和分页底部留白也依赖它。
- [PR #266](https://github.com/Aliothmoon/MAA-Meow/pull/266) 增加启动成功后切到日志页，明确目的是方便查看运行日志，但没有同步调整操作栏。
- 现有点击分支对 LOG 执行 `else -> {}`，单纯放开显示条件会产生无效按钮。

目前查阅的代码、提交和 #266 讨论没有说明必须在日志页隐藏停止和快捷选项的理由。日志页缺少明确的启动对象，是保留启动限制的合理考虑，但这属于分析推断。

## 2. 目标与范围

让用户在日志页完成「观察运行情况 → 停止任务 / 熄屏挂机」，保留现有启动成功后自动跳转的行为。

本次修改面向应用内「任务」页面的日志标签页，即 `BackgroundTaskView`。前台悬浮控制面板 `ExpandedControlPanel` 有独立的布局和按钮语义，不纳入本次 PR。

日志页不增加启动或重跑入口，不保存“上次启动的任务”，不新增用户设置。前三个标签页的启动对象、权限引导和寻访免责声明规则继续沿用现有行为。底层熄屏、屏保、权限和定时策略不在本次功能范围内。

## 3. 交互规则

沿用 `MaaCompositionService.state`，不建立另一套运行状态。

| 状态 | 日志页主操作区域 | 快捷选项 |
| --- | --- | --- |
| IDLE | 显示灰色「停止任务」，不可点击 | 显示，可点击 |
| ERROR | 显示灰色「停止任务」，不可点击；错误仍通过现有日志/提示呈现 | 显示，可点击 |
| STARTING | 显示禁用的启动中进度，与现有启动栏一致 | 显示，可点击 |
| RUNNING | 显示「停止任务」，可点击 | 显示，可点击 |
| STOPPING | 显示禁用的停止中进度 | 显示，可点击 |

STARTING 阶段不新增取消能力。快捷选项入口可用不代表内部所有操作都可用，内部仍遵循现有状态和权限限制。

布局规则：

- 运行时主操作占剩余宽度，「快捷选项」按内容宽度显示，与前三页一致。
- 空闲时两按钮的位置和宽度与运行时一致，「停止任务」使用主题的禁用样式及真正的 `enabled = false`，不只是修改文字颜色；无障碍语义也应标记为禁用。
- 各状态下底栏高度保持稳定，日志末行和“回到底部”按钮不能被覆盖。
- 任务结束后停留在日志页，「停止任务」变灰且不可点击，快捷选项保留。
- 从日志页打开设置搜索命中的快捷选项时，直接展开，不再强制切到一键长草。
- 日志页允许展开快捷选项；返回键、外部关闭操作、全屏预览、确认对话框继续遵循现有浮层管理规则。

仅旁路任务目前可能没有 Core 运行态，按实际状态显示禁用的停止任务和可用的快捷选项，不虚构可停止状态；旁路任务取消能力另行讨论。

## 4. 实现设计

### 4.1 分开“可以启动任务”和“可以使用快捷选项”

保留 `PanelTab.canShowTaskActions()` 的原语义，避免修改共享方法影响前台悬浮面板或其他调用方。

在后台任务页集中定义操作栏展示规则：前三页使用现有主操作规则；LOG 使用上表中的运行控制规则。快捷选项允许四个标签页访问。寻访免责声明只影响对应的小工具页面，不影响日志页。

显示底栏、分页留白、快捷选项收起条件、设置搜索落点使用一致的展示规则，避免分别追加条件后产生不一致。将辅助规则限制在后台任务 UI 范围；如需提取状态模型，应保持简小，不建立通用动作框架。

### 4.2 日志页停止当前会话

日志页的停止目标是当前运行会话，与当前浏览的标签页无关。不根据上一个标签页猜测任务来源，也不同时调用多个 ViewModel 的停止方法。

新增明确的日志页停止回调，放在 ViewModel 层。沿用 `MaaCompositionService.stop()` 的用户停止语义（`StopOrigin.USER`），保留通知和 `TaskEndRegistry` 的手动停止收尾规则。点击入口检查当前状态为 RUNNING，并防止快速重复点击产生并行停止请求；进入 STOPPING 后按钮禁用。

需要同步处理已有入口附带的收尾：

| 现有入口 | 除底层停止外的行为 | 新入口需要核对的结果 |
| --- | --- | --- |
| BackgroundTaskViewModel.onStopTasks | 记录手动停止成就事件 | 新入口按同一语义记录一次 |
| CopilotViewModel.onStop | 更新状态文案、重置当前作业索引 | 停止后切回自动战斗页不会保留错误运行状态 |
| ToolboxViewModel.onStop | 更新状态文案；寻访分支取消提示轮播 | 停止后不会继续运行提示轮播 |
| MiniGameDelegate.onStop | 更新状态文案 | 小游戏页面正确反映停止结果 |

推荐利用现有会话结束通知或会话状态观察完成必要的 UI 收尾，让收尾不依赖用户在哪个页面点击停止。仅清理本次会话涉及的运行状态，不清空其他页面的配置或未执行内容。实现时核对会话关联信息与通知时序，避免上一轮的延迟收尾覆盖新一轮状态。

实现采用 `TaskStopObserver`：各页面成功启动后仅观察本次会话的状态和停止结果，不再次调用停止。通过现有运行 token 排除上一轮的延迟收尾。服务在发布 IDLE 前记录停止结果，避免状态流合并短暂 STOPPING 后遗漏收尾。日志页停止入口检查 RUNNING 并保护在途请求。小工具轮播清理绑定到原 Job，避免取消下一轮轮播。不得直接通过当前选中的小工具标签判断运行来源。

停止失败沿用现有服务的结果和日志机制，不添加无条件的“停止成功”提示。

### 4.3 快捷选项与日志布局

复用 `BackgroundMoreActionsOverlay` 和原有 `onScreenOff` / 屏保回调，保持硬件熄屏开关及确认流程。

继续使用 `BottomBarOverlay` 测量底栏高度，并为日志分页预留该高度。现有组件隐藏时仍会测量底栏，不能仅修改 `showBottomBar` 而忽略 `reserveBar`。

保留日志自动滚动、用户向上阅读、恢复跟随、清空和导出行为。操作栏应在日志列表之外，不随日志滚动。

现有用户可见文案优先复用资源；如新增状态说明，按项目现有语言资源同步补齐。

### 4.4 日志尺寸与滚动专项检查

已完成源码及现有测试检查，结论如下；这些结论尚未经设备运行验证。

| 检查项 | 当前实现与影响 | 实现要求 |
| --- | --- | --- |
| 底栏遮挡 | `BottomBarOverlay` 将底栏放在内容上方；LOG 当前不预留底部高度 | 日志页从首次布局开始就预留实测底栏高度，不能只让按钮显示出来 |
| 状态切换 | 底栏文字、进度和禁用样式可能改变测量结果 | 两个按钮常驻，保持相同容器、内边距和高度规则；验证文字/进度切换时日志视口不抖动 |
| 列表可滚动性 | `LogPanel` 的标题下方使用 `weight(1f)` 的容器及 `LazyColumn` | 正确留白后列表仍可滚动，但可视行数减少；小屏横屏需检查实际剩余高度 |
| 自动跟随末尾 | 滚动副作用只以末条日志 ID 和 `isAutoScroll` 为键 | 视口缩小且没有新日志时，不会主动重新定位末尾，存在末条暂时不可见的风险 |
| 手动阅读 | `rememberLazyListState()` 保存滚动状态，日志条目以 ID 为 key | 不能因运行状态变化而重建 LogPanel；尺寸调整时优先保持原阅读条目和偏移，不能无条件滚到底部 |
| 回到底部按钮 | 按钮位于日志列表容器右下角，依赖 `canScrollForward` 显示 | 整个 LogPanel 预留底栏空间后该按钮随容器上移；验证没有重叠、可点击 |
| 日志行与详情 | 列表文字最多显示三行，完整内容由详情弹窗承载 | 检查窄屏换行和长日志详情；原有省略显示不是新增底栏造成的内容丢失 |

处理策略：日志页始终预留底栏空间，预留规则按该分页确定，不随当前选中的其他标签页改变。复用实测高度，不写死一个只适合默认字体的数值，也不叠加两次底部留白。

对于窗口缩放、横竖屏布局变化或字体导致的视口变化，在布局完成后观察有效视口尺寸：仅当自动跟随仍开启且用户没有正在拖动时，重新定位最新日志；手动阅读状态下保留滚动位置。重新定位前检查当前跟随状态，避免排队中的尺寸事件把正在阅读的用户拉回底部。尺寸观察需去重，避免观察整个列表布局信息并因滚动反复触发自己。

现有 `isScrollInProgress` 会在滚动时关闭跟随；增加程序性定位时需验证不会误关闭跟随。优先沿用现有定位方式，以行为测试决定是否需要区分用户拖动与程序性滚动。

日志满上限后被删除的旧条目无法保留阅读锚点，验收应使用仍存在的条目。横竖屏若触发 Activity 重建，跟随标志目前仅使用 `remember`，其恢复行为也应单独记录；它不是常驻底栏能够自动解决的问题。

既有测试覆盖日志满上限后跟随、隐藏页停止收集，以及底栏首次测量与隐藏时尺寸保留。本次已补充真实日志面板与底栏组合的缩放、末条遮挡、程序性定位后继续跟随，以及手动阅读和恢复跟随测试；另补停止按钮各状态的禁用/点击与尺寸稳定测试。这些 Android 测试尚未在设备运行。

## 5. 验收与验证计划

以下为验收场景清单，实际完成情况见第 7 节；不代表所有场景已在设备验证通过。

| 场景 | 预期 |
| --- | --- |
| 空闲或错误状态进入日志页 | 停止任务置灰且不可点击、无停止调用，快捷选项可用，无开始任务按钮 |
| 一键长草启动成功并自动跳日志 | 显示停止任务和快捷选项，无需切页 |
| 启动中手动进入日志 | 主操作为禁用进度，可访问快捷选项 |
| 在日志页停止任务、快速重复点击 | 只发起一次停止，停止中禁用，结束后停止任务置灰；按钮和日志视口尺寸稳定 |
| 自动战斗 / 小游戏 / 寻访运行时手动切日志并停止 | 当前会话停止，原页面文案、作业索引和轮播正确收尾 |
| 启动后切换过多个标签页再进入日志 | 停止目标仍为当前会话 |
| 定时启动后进入日志 | 可停止当前会话，不依赖手动启动入口的页面历史 |
| 自然结束、异常结束 | 主操作随实际状态变化；快捷选项仍可访问 |
| 仅旁路任务 | 无虚假运行或停止状态，日志仍可阅读 |
| 日志页开启熄屏挂机 | 屏保及硬件熄屏分别沿用原流程，唤醒后任务状态正确 |
| 快捷选项展开时返回、进入全屏或出现确认框 | 浮层按既定规则关闭，不遮挡后续操作 |
| 搜索命中快捷选项设置且当前在日志页 | 原地展开并定位，不跳一键长草 |
| 长日志、日志满上限、手动上翻、恢复跟随 | 日志末行不被底栏覆盖，滚动行为正确 |
| 自动跟随中缩小视口，不追加任何日志 | 完成重新布局后最新日志仍可见，跟随不会被意外关闭 |
| 手动上翻后缩放窗口或切换任务状态 | 仍在阅读原有且未被淘汰的日志，未被拉回末尾；恢复跟随按钮可用 |
| 小屏下日志与底栏组合布局 | 末行及恢复跟随按钮不与底栏相交，滚动和点击区域正确 |
| 小屏、横屏、大字体、自定义背景 | 操作可见可点击，底栏布局和主题正确 |
| 前三页、寻访未确认免责声明、前台悬浮面板 | 原有启动限制及布局无回归 |

自动化测试以关键行为为主：状态到操作栏的映射、单次停止请求、结束后的必要清理、底栏不遮挡日志。复用已有 `BottomBarOverlayTest`、`LogPanelAutoScrollTest` 的基础设施，仅补充新增交互所需的场景。

实现后按 [构建指南](BUILDING.md) 准备环境，执行相关 JVM 测试及 Debug 构建；Compose 和熄屏操作需要相应测试设备。提交 PR 时记录实际设备、Android 版本、Shizuku / Root 方案和通过的命令；无法完成的验证明确列为未执行。
