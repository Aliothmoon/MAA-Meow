# Issue 规范

本文档用于统一 MAA Meow 的 Issue 标题，让贡献者和维护者在列表页中无需打开正文，就能判断 Issue 的类型、影响模块和具体问题。

新建 Issue 时可选择中文或英文表单，两者字段一致。

## 标题格式

```text
[类型][模块] 具体问题或需求
```

通过 Bug 反馈 / 功能建议表单提交时，**标题只需填写「具体问题或需求」**。提交后会根据表单类型和所选「功能模块」自动补全前缀，例如填写 `启动任务后应用闪退` 并选择 `后台模式`，标题会变为 `[Bug][后台模式] 启动任务后应用闪退`。

手写的 `[Bug]`、`【BUG】`、`[Feature]` 等类型标签会被替换，其他前缀（如 `[国际服]`）保留。

### 类型

| 标签 | 来源 | 适用场景 |
|------|------|----------|
| `[Bug]` | Bug 反馈表单 | 已有功能出现错误、崩溃或与预期不符 |
| `[Feature]` | 功能建议表单 | 新功能或已有功能的增强建议 |

文档、构建、使用咨询等其他问题，请使用空白 Issue 或 [Discussions](https://github.com/Aliothmoon/MAA-Meow/discussions)。

### 模块

选择**最先出现异常**的位置。问题跨越多个模块时，在正文中补充其他影响范围。

| 模块 | 范围 |
|------|------|
| `开始唤醒` / `理智作战` / `自动公招` / `基建换班` / `信用收支` / `领取奖励` / `自动肉鸽` / `生息演算` | 一键长草中对应任务的识别、操作或执行结果；访问好友归入 `信用收支` |
| `其他长草任务` | 更新数据、库存保持、干员培养、更换主题、关闭游戏、自定任务等 |
| `自动战斗` | 抄作业、悖论模拟等自动战斗页的功能 |
| `小工具` | 公招识别、仓库识别、干员识别、牛牛抽卡等 |
| `定时任务` | 定时触发、唤醒、到点未启动 |
| `前台模式` | 前台模式特有的问题，如横屏、主屏显示 |
| `后台模式` | 虚拟显示器相关：黑屏、游戏跑回主屏、进程被杀 |
| `权限与服务连接` | Shizuku / Root 授权、服务启动失败、MAA 服务崩溃或断开 |
| `通知` | 系统通知与外部通知推送 |
| `安装与更新` | 安装包、应用更新、资源下载与初始化 |
| `界面与设置` | 首页、设置页、悬浮窗与控制面板的显示和交互 |
| `其他` | 以上都不适用 |

### 摘要

- 直接写明“在什么场景下，发生了什么”，避免只写“异常”“不能用”“有问题”等泛化描述。
- 描述实际现象，不要只写期望结果。
- 保持简洁，不在标题中堆叠设备型号、版本号、日志或完整复现步骤；这些信息应写入正文。
- 标题末尾不加句号。

## 示例

| 填写的标题 | 所选模块 | 最终标题 |
|------------|----------|----------|
| `启动任务后应用闪退` | 后台模式 | `[Bug][后台模式] 启动任务后应用闪退` |
| `[Bug] 到达设定时间后任务未启动` | 定时任务 | `[Bug][定时任务] 到达设定时间后任务未启动` |
| `支持按干员职业筛选作业` | 自动战斗 | `[Feature][自动战斗] 支持按干员职业筛选作业` |

| 不推荐 | 原因 |
|--------|------|
| `有问题`、`[Bug]` | 看不出发生了什么 |
| `定时任务不能用` | 没说明具体故障：是没触发、没唤醒，还是执行出错 |
| `希望加个筛选` | 没说明在哪筛选、按什么筛选 |

## 功能建议的判断信息

功能建议应提供足够信息，让维护者能够判断需求价值和实现范围：

- **使用场景与现有问题**：在什么情况下遇到了什么困难，现有方式为什么不足。
- **建议方案**：期望的行为或交互，不要求给出具体代码实现。
- **完成标准**（选填）：怎样算实现了这个建议。
- **替代方案**（选填）：如有临时解决方式或考虑过的其他方案，请说明其局限。

一个 Issue 只讨论一个主要建议。互不相关的需求应分别提交，以便独立评估、跟踪和关闭。

## 提交前检查

- [ ] 标题写清了具体问题或需求
- [ ] 所选模块与正文内容一致
- [ ] 已搜索现有 Issue，确认没有重复提交

不符合规范的标题可能由维护者直接调整。若 Issue 实际包含多个互不相关的问题，请拆分为多个 Issue。
