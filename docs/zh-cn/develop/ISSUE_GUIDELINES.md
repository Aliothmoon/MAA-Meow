# Issue 规范

本文档用于统一 MAA Meow 的 Issue 标题，让贡献者和维护者在列表页中无需打开正文，就能判断 Issue 的类型、影响模块和具体问题。

新建 Issue 时可选择中文或英文表单。两种语言使用相同的标题结构和信息要求；标题中的模块可使用对应语言。

## 标题格式

```text
[类型][模块] 具体问题或需求
```

标题由三部分组成：

1. **类型**：使用固定英文标签。
2. **模块**：使用稳定、简短的功能名称。
3. **摘要**：描述可观察的故障现象或明确需求。

### 类型

| 标签 | 适用场景 |
|------|----------|
| `[Bug]` | 已有功能出现错误、崩溃或与预期不符 |
| `[Feature]` | 新功能或已有功能的增强建议 |
| `[Docs]` | 文档缺失、错误或改进建议 |

### 模块

优先使用以下名称：`首页`、`任务配置`、`前台模式`、`后台模式`、`定时任务`、`自动战斗`、`工具箱`、`设置`、`安装更新`、`构建`、`文档`。无法归类时使用 `其他`。

同一个 Issue 只填写一个主要模块。问题跨越多个模块时，选择最先出现异常或受影响最大的模块，并在正文中补充其他影响范围。

### 摘要

- 直接写明“在什么场景下，发生了什么”，避免只写“异常”“不能用”“有问题”等泛化描述。
- 描述实际现象，不要只写期望结果。
- 保持简洁，不在标题中堆叠设备型号、版本号、日志或完整复现步骤；这些信息应写入正文。
- 标题末尾不加句号。

## 示例

| 推荐 | 不推荐 | 原因 |
|------|--------|------|
| `[Bug][后台模式] 启动任务后应用闪退` | `[Bug] 后台有问题` | 缺少统一模块，现象不明确 |
| `[Bug][定时任务] 到达设定时间后任务未启动` | `定时任务不能用` | 缺少类型，无法判断具体故障 |
| `[Feature][自动战斗] 支持按干员职业筛选` | `希望加个筛选` | 缺少模块和明确需求 |
| `[Docs][构建] 补充 Windows 环境的 JDK 配置说明` | `更新文档` | 无法从标题判断改动范围 |

## 功能建议的判断信息

功能建议除遵循标题规范外，还应提供足够信息，让维护者能够判断需求价值、实现范围和完成条件：

- **使用场景与现有问题**：谁在什么情况下遇到了什么困难，现有方式为什么不足。
- **建议方案**：期望的行为或交互，不要求给出具体代码实现。
- **完成标准**：列出可验证的结果，避免只写“更好用”“优化体验”。
- **替代方案**：如有临时解决方式或考虑过的其他方案，请说明其局限。

一个 Issue 只讨论一个主要建议。互不相关的需求应分别提交，以便独立评估、跟踪和关闭。

## 提交前检查

- [ ] 标题符合 `[类型][模块] 具体问题或需求` 格式
- [ ] 类型和模块与正文内容一致
- [ ] 仅查看标题即可理解主要问题或需求
- [ ] 已搜索现有 Issue，确认没有重复提交

不符合规范的标题可能由维护者直接调整。若 Issue 实际包含多个互不相关的问题，请拆分为多个 Issue。
